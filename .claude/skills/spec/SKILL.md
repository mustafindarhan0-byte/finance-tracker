# /spec — идея → спека

Результат: файл `assets_src/SPEC_<тема>.md`, по которому `/build` работает без вопросов, а `/review` может проверить каждый пункт.

1. **Разведка.** По `CODEMAP.md` и `node tools/codemap.cjs who/find` найди, что уже есть рядом (данные, экраны, похожие функции). Прочитай только эти куски index.html. Готово, когда можешь назвать функции и коллекции, которые фича затронет.
2. **Интервью.** Задавай вопросы пачкой по 3–5, нумерованно, у каждого — твой вариант по умолчанию. Пользователь отвечает коротко («1. да 2. позже»); пустой ответ = вариант по умолчанию. Повторяй, пока не закрыты: что видит пользователь, где это в интерфейсе, какие данные хранятся и где, что считается успехом, что точно вне рамок.
3. **Запись.** Структура файла:
   - Цель — одна-две фразы, зачем это пользователю.
   - Вне рамок — список.
   - Данные — новые коллекции/поля/settings; нужна ли правка `firestore.rules`; миграция старых данных.
   - Пункты `X1…Xn` (буква — тема спеки). Каждый пункт: что сделать + **критерии приёмки**, каждый проверяемый: тест (`tests/<файл>.cjs`, что утверждает) или шаг в браузере (действие → ожидаемый результат). Пункты упорядочь так, чтобы каждый можно было закоммитить отдельно.
   - Риски — синк между устройствами, старые данные, мобильная ширина 375 px.
4. **Сдача.** Покажи пользователю краткое оглавление пунктов (одна строка на пункт) и спроси, запускать ли `/build`.

Спека готова, когда у каждого пункта есть хотя бы один проверяемый критерий и в файле не осталось открытых вопросов.
